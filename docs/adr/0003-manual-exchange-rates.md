# Manual exchange rates and order price snapshots

Prices are stored in USD; display conversion uses manually-maintained `currencies` rows (rate per 1 USD) rather than a live FX API, and every Order snapshots the USD price plus the rate in effect at checkout so later rate changes never alter history. A live FX API was rejected: it adds an external dependency and nondeterministic pricing. Manual rates keep pricing predictable and auditable; settlement always happens in the gateway's own currency regardless of the display currency.

The `currencies` table (code, name, symbol, exchange_rate, decimal_places, is_enabled, is_default) replaced the earlier `exchange_rates` table and the `DisplayCurrency` enum. One row is marked `is_default` — the base currency (rate 1) used for prices and as the guest/user fallback; its rate and enablement are forced by the model's `saving` hook and it cannot be deleted (`deleting` hook throws). String columns (`users.display_currency`, `orders.currency`, `orders.settlement_currency`) hold currency codes without an enum cast or foreign key; callers resolve them via `Currency::required()` / `Currency::fromCode()` / `Currency::default()`, failing loudly when a code is not configured.
